## 2. Felice 今天的角色

Felice 今天不是来“玩一个游戏”，而是担任：

```text
Sailing Realism Reviewer / 帆船真实感导演
```

AI 可以写代码，但 AI 没有真实帆船手感。Felice 的价值是判断：

| Felice 判断的问题 | 例子 |
|---|---|
| 像不像真实帆船 | 这个船是不是太容易逆风了 |
| 哪里会误导初学者 | 初学者可能以为大舵角没有速度代价 |
| 真实情况应该怎样 | 接近风眼时应该掉速、帆会 luffing |
| 改完后是否变好 | 修改后是否更接近真实换舷体验 |

Eric 和 Codex 的任务是把这些判断转成小范围代码修改、测试和可试玩版本。

## 3. 今天只看一个主问题

推荐第一节课聚焦：

```text
迎风 no-go zone + tack 换舷真实感
```

为什么先看这个：

| 原因 | 说明 |
|---|---|
| 教学价值高 | 能解释为什么帆船不能直接逆风 |
| 专业判断明显 | 帆船同学很容易判断“像不像” |
| 适合小范围修改 | 可以先改 HUD、掉速、大舵角速度代价 |
| 展示效果好 | 修改前后可以用同一个场景对比 |

如果 Felice 试玩后觉得另一个问题更重要，也可以改成：

```text
稳向板和侧滑
```

但今天只选一个方向，不同时改很多系统。

## 7. 场景 1：迎风 no-go zone

操作方式：

1. 让船先有一定速度。
2. 慢慢转向风眼。
3. 观察船速、帆状态、航向是否还能轻松穿过风眼。

Eric 只追问这些问题：

```text
现在这个表现像真实船吗？
真实帆船接近风眼时应该有什么变化？
这里是速度不对、帆不对、舵不对，还是屏幕没解释清楚？
如果初学者看到这个，会学错什么？
```

记录：

| 问题 | Felice 观察 |
|---|---|
| 当前模拟器表现 |  |
| 真实帆船应该怎样 |  |
| 是否太容易逆风 |  |
| 是否明显掉速 |  |
| 帆是否应该 luffing / stalled / backwinded |  |
| 严重程度：高 / 中 / 低 / 争议 |  |

## 8. 场景 2：Tack 换舷

操作方式：

1. 让船在可航行角度获得稳定速度。
2. 用 `A / D` 逐步转向风眼并换舷。
3. 观察掉速、帆换边、舵效、大舵角速度代价。

Eric 只追问这些问题：

```text
真实 tack 时最明显的手感是什么？
现在换舷是不是太顺滑？
帆换边是不是太快或太慢？
大舵角是否应该让船变慢？
改完以后你怎么判断它变好了？
```
